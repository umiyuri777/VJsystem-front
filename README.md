### 1. 制作物イメージ
[!['デモ動画'](https://img.youtube.com/vi/K8LxlCLNzxQ/hqdefault.jpg)](https://youtu.be/K8LxlCLNzxQ)

### 2. 概要

ハッカソンで制作した．
スクリーンで行われているVJに対して，観客が参加できることをコンセプトにした．
観客は赤チーム・白チームの2つに別れ，観客のスマホを振ることによって参加できる．
VJの判断によってチームの対決が発生し，2つの画面に別のエフェクトが発生する．
チーム全体の振った回数の合計値によって勝利チームが決定し，勝利チームのエフェクトが画面全体に表示される

### 3. あなたの役割

- 観客の画面の作成・バックエンドへのリクエスト処理
- スプレッドシートへの記録

### 5. 工夫したこと・苦労したこと

観客側からの振った回数の送信は，振った回数をフロント側で1秒間プーリングしてから送るようにしている．
これによってリクエストの回数が **参加人数/s**回 まで削減できる．

スプレッドシートへの書き込みの際はユーザーを識別し，ユーザーごとに別の列に書き込むように工夫した．

最終発表で20人ほどの前で発表することが決まっていたため，事前に負荷検証ツールであるk6を使用し，負荷検証を行なった．その結果，20人規模であっても同時にリクエストが来ると同じセルに同時に書き込んでしまう問題が発覚した．

そのため，シートに排他制御をかけて書き込みが同時に行わないように変更したが，そうすると同じセルに書き込んでしまう問題は解消したが，1回のリクエストの処理にかかってしまう時間が長くなってしまい，リアルタイム性が低下する問題が発生した．参加型VJというリアルタイム性を重視したい今回のプロダクトの要件には合わないと判断した．

観客側にユーザーIDを付与し，ユーザーごとに列を分けることによって同じセルに書き込間れることが最大限少なくなるように工夫した
